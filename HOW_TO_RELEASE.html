GATA firmware releases & customer uploaders

The model: one updater app. Each company gets a folder copy containing their license file (gata.license) and their offline .bin files. The license carries the company name and automatically connects their cloud updates to their channel. Channels today:

CompanyChannelLicense file (already made)Publish flag
General (everyone)defaulttools\licenses\General.gata.license(no flag)
KSPksptools\licenses\KSP.gata.license-Customer ksp
Danwaydanwaytools\licenses\Danway.gata.license-Customer danway
Every command below runs in PowerShell, from D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools unless said otherwise.

Leave -Version out and the name is made for you: 20_08_26_KSP_rev5 (day_month_year_Company_board). The version is signed, gets its own .lic package license automatically, and the script pushes it to GitHub — every customer's app sees it on next start. Skip -EspDir? Then it reuses the ESP files already in the folder. No new system firmware? You can leave -System out too (it reuses the newest one).
If the push fails with git.gatasys.com authentication (the company mirror), the GitHub publish usually still went through. To push GitHub by hand: 
git -C D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\firmware push https://github.com/gata2024/gata-firmware.git main

2  Build a customer's uploader folder (offline files + their license)

Example for KSP — replace ksp/KSP with danway/Danway for Danway.

Step 1 — copy the app (WITHOUT your secret keys and the server folder)

robocopy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader" "D:\Uploader_KSP" /E /XD .git firmware tools android tests c .playwright-mcp dist /XF gata.license

Step 2 — put THEIR license in

copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools\licenses\KSP.gata.license" "D:\Uploader_KSP\gata.license"

Step 3 — put THEIR offline .bin files in

Take the files of the version you published for them (they are in the firmware\ folder after publishing):

copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\firmware\controller_20_08_26_KSP_rev6.bin" "D:\Uploader_KSP\main_firmware\"
copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\firmware\system_20_08_26_KSP_rev6.bin"     "D:\Uploader_KSP\main_firmware\"
copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\firmware\esp\20_08_26_KSP_rev6\*"          "D:\Uploader_KSP\cloud_firmware\"

(Adjust the version name to the one you actually published. Delete any OLD bins already in main_firmware\ first so there is no confusion.)

Step 4 — send the whole D:\Uploader_KSP folder (zip it)

The customer runs CLICK_ME_START_ON_PC.bat. The app licenses itself as KSP from the file, works offline with the included bins ("Use the files in the uploader folder"), and gets KSP cloud updates automatically whenever they have internet. Nothing to type, ever.

Never include in a customer copy: tools\ (has signing_key.json + license_key.json — the keys of the whole system), firmware\ (the whole server repo), android\ (the store keystore). The robocopy command above already excludes them.

3  Where to put .bin files manually (offline updates)

Inside any uploader folder — yours or a customer's:

FolderFilesNaming
main_firmware\system firmware + controller software system_<anything>.bin and controller_<anything>.bin (old names B1.bin/M*.bin also work)
cloud_firmware\the 4 ESP32 files exactly: bootloader.bin, partitions.bin, boot_app0.bin, firmware.bin

Then in the app press “Use the files in the uploader folder” → Scan again if needed.

5  Back these up (they ARE the business)

  • tools\signing_key.json — signs every firmware list; without it you cannot release.
  • tools\license_key.json — mints licenses; anyone holding it can license anything.
  • android\gata-release.keystore — signs the Android app.
  • tools\licenses_issued.txt + tools\licenses\ — every license you ever issued.
