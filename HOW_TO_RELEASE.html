GATA firmware releases & customer uploaders

The model: one app per company. Each company gets a folder copy containing their license file (gata.license) and their offline .bin files, and — for phones — their own page at c\<channel>\ with their own Android app. The license carries the company name and connects their updates to their channel. 👉 The easy way: GATA_Release_Manager.exe

Double-click it in the uploader folder and do everything with buttons — no commands at all:
  • PUBLISH TO CLOUD — pick the company + boards, press once. Both board revisions in one go.
  • BUILD CUSTOMER UPLOADER FOLDER — makes their ready-to-send folder: app + their license file + their latest firmware, with your keys automatically left out.
  • In the cloud right now — the list at the bottom shows exactly what the selected company can download today (the bold NOW row is what their app offers as “Latest”). Pick a row and press Remove selected to take a release back: its files are deleted, the list is re-signed and pushed, and the previous release becomes the latest again. Controllers already updated are not affected.
  • CHECK A FOLDER — re-checks a prepared customer folder: every .bin against its delivery receipt and against the files selected above.
  • FIRMWARE INSIDE THE APP — puts the chosen .bin files inside the app, so a phone can install with no internet. General writes the site root; a company writes their own page (c\<channel>\). The phone still downloads it once, on its first launch with internet, and keeps it from then on. Deploy afterwards (git push) or it reaches nobody. Unticking Cloud module (ESP32) removes the ESP firmware already inside that app.
  • ANDROID APP (.apk) — builds that company's app: its own package name, its own page, its own license and its own built-in firmware (dist\gata-updater.apk, dist\gata-updater-<channel>.apk). It rebuilds their page first, so publish the app before pressing it. A firmware release never needs a new apk — the app is a thin wrapper around the page.
  • Add new company… — creates their channel and their license file. Their app page is built later, by ANDROID APP, once their firmware is chosen.
  • Back up keys — copies both keys, the keystore and all issued licenses to a USB stick.
It runs the very same scripts described below and prints every command it used, so you can always check or repeat it by hand. Never send this program to a customer — it is your release tool.
If it is missing, build it once: 
cd D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools
.\build_release_manager.ps1

2  Build a customer's uploader folder (offline files + their license)

Example for KSP — replace ksp/KSP with danway/Danway for Danway.

Step 1 — copy the app (WITHOUT your secret keys and the server folder)

robocopy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader" "D:\Uploader_KSP" /E /XD .git firmware tools android tests c .playwright-mcp dist /XF gata.license

Step 2 — put THEIR license in

copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools\licenses\KSP.gata.license" "D:\Uploader_KSP\gata.license"

Step 3 — put the .bin files in

Copy the same three build outputs you publish with, renaming them so the company and board are visible (controller_<dd_MM_yy>_<Company>_<rev>.bin). Delete any old bins there first.

copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\g_500\Debug\NPC20_mini.bin" "D:\Uploader_KSP\main_firmware\controller_20_08_26_KSP_rev6.bin"
copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\USBupdaterCode_relbuild\Debug\Booster_phase.bin" "D:\Uploader_KSP\main_firmware\system_20_08_26_KSP_rev6.bin"
copy "D:\emirates\saudi\makeLogicwork\gc22SramToflash\esp\.pio\build\esp32dev\*.bin" "D:\Uploader_KSP\cloud_firmware\"

The ESP files must keep their exact names (bootloader.bin, partitions.bin, boot_app0.bin, firmware.bin) — the app looks for those four. The Release Manager button does all of this for you, using the files shown in its window.

Step 4 — send the whole D:\Uploader_KSP folder (zip it)

The customer runs CLICK_ME_START_ON_PC.bat. The app licenses itself as KSP from the file, works offline with the included bins ("Use the files in the uploader folder"), and gets KSP cloud updates automatically whenever they have internet. Nothing to type, ever.

Never include in a customer copy: tools\ (has signing_key.json + license_key.json — the keys of the whole system), firmware\ (the whole server repo), android\ (the store keystore). The robocopy command above already excludes them.

3  Where to put .bin files manually (offline updates)

Inside any uploader folder — yours or a customer's:

FolderFilesNaming
main_firmware\system firmware + controller software system_<anything>.bin and controller_<anything>.bin (old names B1.bin/M*.bin also work)
cloud_firmware\the 4 ESP32 files exactly: bootloader.bin, partitions.bin, boot_app0.bin, firmware.bin

Then in the app press “Use the files in the uploader folder” → Scan again if needed.

3b  Taking a release back off the cloud

cd D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools
.\remove_version.ps1 -Version 20_08_26_KSP_rev5 -Customer ksp
.\remove_version.ps1 -Version 19_08_26_General_rev6            # the shared/General channel

Deletes only the files that release used, re-signs the list and pushes it. The newest remaining release becomes “latest”, and it refuses to remove the last release of a channel. The Release Manager does this from its list (section 5, “Remove selected”).

4b  Their phone app (one per company)

A company's Android app opens their own page, so it carries their license, their channel and their own built-in firmware. Build the page first, publish it, then build the app:

cd D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools
.\build_customer_site.ps1 -Id acme -Board rev6 `
   -Controller ..\..\g_500\Debug\NPC20_mini.bin `
   -System ..\..\USBupdaterCode_relbuild\Debug\Booster_phase.bin `
   -EspDir ..\..\esp\.pio\build\esp32dev
cd D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader
git add . ; git commit -m "ACME app" ; git push
cd D:\emirates\saudi\makeLogicwork\gc22SramToflash\GATA_Cloud_Uploader\tools
.\build_android_app.ps1 -Id acme -Name "ACME Water"

General is the site root, not a c\ folder — refresh its built-in firmware with .\refresh_builtin.ps1 instead, and build its app with no -Id.

Two things that are easy to get wrong.
  • Changing the firmware inside an app reaches phones only after a git push, and only on their next launch with internet. The app itself never needs rebuilding for that.
  • Every new package name needs an entry in .well-known/assetlinks.json on gata2024.github.io (same signing key), or the app opens with a browser address bar. build_android_app.ps1 prints the exact entry to paste.

5  Back these up (they ARE the business)

  • tools\signing_key.json — signs every firmware list; without it you cannot release.
  • tools\license_key.json — mints licenses; anyone holding it can license anything.
  • android\gata-release.keystore — signs the Android app.
  • tools\licenses_issued.txt + tools\licenses\ — every license you ever issued.
